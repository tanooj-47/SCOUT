# SCOUT — Frontend Application Architecture

**Milestone:** 13.1  
**Project:** SCOUT — Multimodal Disaster Intelligence & Response Platform  
**Location:** `frontend/`  
**Framework:** React 18+ with TypeScript, Vite 5, Tailwind CSS 3, MapLibre GL JS 4, TanStack Query 5  

---

## 1. Architectural Overview

The SCOUT frontend application provides a mission-critical, human-in-the-loop decision-support interface for emergency managers, incident commanders, and disaster intelligence analysts. It integrates telemetry, machine learning inferences, environmental indexing, and multi-agent workflow orchestration from the SCOUT FastAPI backend.

### Core Architecture Principles

1. **Advisory Decision Support:** Zero autonomous dispatch. All actionable recommendations generated by upstream agents are held at an explicit Human Review Gate requiring authorized incident commander review.
2. **Epistemic Integrity & Uncertainty Qualification:** Model probability scores (e.g. from M07 CNNs) are displayed as raw visual activations rather than calibrated real-world probabilities. All perceptual and atmospheric limitations are explicitly surfaced.
3. **High-Precision Spatial Anchoring:** Built on MapLibre GL JS with native WGS 84 (EPSG:4326) coordinates, geodesic distance metrics, and automatic UTM zone projection resolution.
4. **Resilient Data Fetching:** Managed by TanStack Query with background polling, automatic deduplication, and stale-time caching for live situational awareness.

## 5. Human Approval Gate & Reviewer Authentication

In compliance with the M12.4 and M12.5 specifications:
1. When submitting decisions at `/api/v1/workflows/{id}/approval`, the client transmits:
   - Header: `Authorization: Bearer <reviewer-token>`
   - Header: `X-Reviewer-Token: <reviewer-token>`
2. Token storage: Configurable via UI Topbar or Settings page, stored in `localStorage` (`scout_reviewer_token`), defaulting to `reviewer:commander-01`.
3. Mandatory written explanation:
   - `approved`: Optional commander operational notes.
   - `rejected`: **Mandatory** written justification reason. Submitting without text triggers client-side validation and HTTP 422 enforcement.
   - `needs_revision`: **Mandatory** written justification reason explaining required agent graph re-planning.
4. Non-dispatch contract: The UI clearly reminds operators that approval updates the audit trail and authorizes internal action plans; it does not issue automated dispatch orders.
